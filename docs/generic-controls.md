# 通用进度、定次重复与节奏锚点

模型识别控制含义，执行器负责可计算的时间和完成量。默认不配置随倒计时变化的动作策略，也不把台本进度当成生理状态测量。

## 在哪里配置

继续使用 `config/llm-qwen-local.yaml` 规划、`config/fusion-context.yaml` 融合。知识正文仍在 `config/semantic-knowledge.md`，没有硬编码某份台本的字幕编号或路径。

融合配置新增：

```yaml
progress_curve: []
allow_inferred_controls: false
rhythm_anchors_ms: {}
```

`progress_curve` 是用户自定义的阶梯预设曲线：每点含 `at`（0～1）和已有的 `preset_id`，从0开始、严格递增。空列表仅观察进度，不改变参数。此处不提供预设的刺激或加速曲线。它只在已有可执行活动状态下选择默认预设，不启动运动；明确的速度/幅度要求优先，暂停和人工分段也优先。明确参数变化会抑制本轮后续曲线，直到控制重置或进入新序列。

`allow_inferred_controls` 默认关闭；推断进度仍可显示，但不会驱动曲线。推断的重复或节奏任务也不会执行。是否将推断用于执行由此配置决定。

`rhythm_anchors_ms` 将某个控制起始字幕 ID 映射为人工确认的绝对音频时间列表，单位毫秒，严格递增。配置里需要填写实际字幕 ID，这是数据关联，不是将具体 ID 写进通用提示词。时间必须在音轨内、在该任务起点之后。

## 模型输出

`context_notes` 继续记录来源和解释，可额外带 `control`：

| kind | 字段 | 含义 |
| --- | --- | --- |
| countdown | progress.start_value / end_value / current_value | 起点数、终点数、当前数；归一化进度为 `(start-current)/(start-end)` |
| repetition | count、unit | 要求的重复总量，区分单程 single_travel 与完整往返 round_trip |
| rhythm_follow | unit | 跟随声音的意图；实际时间来自确认过的锚点 |

共同字段 `sequence_cue_id` 指向该控制开始的来源字幕，并要求引用其原文。`status` 支持 update、reset、end。当前数必须在起止范围内，起点必须大于终点；范围不明时只记文字笔记，不捏造数字。相同序列的进度回退未标 reset 时，记录观察值但不执行曲线。

单独的规则定义笔记不会执行；同句另有当前、直接的开始/恢复事件时，可以将定义的约束用于该次活动。数字可能是倒计时、次数或普通叙述；声音文字可能只是引用。模型必须根据上下文区分，不能按出现次数机械生成运动。

必要的开始、暂停、恢复和结束仍通过动作事件表达。`control.status=end` 只结束对应控制，不替代动作侧的暂停指令。

## 定次重复

明确次数和单位后，执行器按已有预设生成有限运动，完成后保持当前位置，不继续无限循环。完整往返定义为“从任务开始位置出发，移动至当前预设的一个端点，再返回开始位置”；开始位置在预设范围中间时，所用幅度可能小于完整 low～high 范围。单程是一次到目标端点的移动；首次也从实际当前位置开始计数。

暂停保留尚未完成的任务和当前运动段；恢复继续剩余部分，不重置已完成数量。明确新建 start 且没有随附任务时，退出旧任务。未完成即结束时报告 incomplete；单位 unknown 时保持位置并报告待确认，不将任意周期运动当成已完成指定次数。

模型不知道设备已经完成了多少次；“继续剩余次数”应引用原任务，不猜剩余数字。实际完成量由执行器记录。同一序列、相同总量和单位的 update 延续原任务，不重新计数；新任务应采用新的起始来源，或明确 reset。

## 节奏锚点

单程模式每个锚点到达一个端点；往返模式每个锚点返回该拍开始的位置，中间放置一个端点。锚点由用户确认，不由模型生成。往返的一拍至少需要2毫秒以表达两个不同时间点。

没有锚点或单位不明时保持位置并记录原因。暂停优先；错过的锚点不在恢复后重放，被中断的一拍不计为完整完成。锚点用尽后保持位置。

目前没有自动识别拟声词或音频节拍的算法。已有音频周期候选也不会自动成为已确认锚点；此版本提供的是已确认时间的执行接口。

## 在哪里检查结果

融合目录的 `segment_plan.json` 新增：

- 每段的 `control`：台本进度、候选/可执行状态和当前任务。
- `control_dispositions`：仅定义、观察、调度、延续、未解析、冲突或结束的处理记录。
- `control_execution`：请求数量、实际完成量及 completed / incomplete / anchors_exhausted 状态。

`mode`、`preset_id` 描述该段的活动预设；有限任务可能在段内提前完成，实际输出以脚本点和 `control_execution` 为准。次数与锚点完成不会强行改变人物的语义状态。

最终脚本仍通过既有时间、位置和设备速度约束检查，约束失败时不导出可执行脚本。
