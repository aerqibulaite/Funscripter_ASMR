# 字幕导入

`subtitles.path` 的 `.srt` / `.vtt` 扩展名（不区分大小写）自动选择 SRT / WebVTT，其余扩展名沿用 LRC。可用 `format: srt`、`format: vtt` 或 `format: lrc` 明确指定；默认 `auto`，旧配置仍可读取。

```yaml
subtitles:
  path: track.srt
  format: auto
  encoding: utf-8-sig
  offset_ms: 0
```

SRT 支持可选序号、逗号或点分隔的毫秒、1–3 位小数、BOM 和多行正文。正文作为输入数据保存，语言、标记及类似指令的文本不会改变导入规则。原文件按字节保存至项目的 `inputs/subtitles.srt`。编码无法解码时需明确配置正确编码，不自动替换字符。

SRT 起止时间和源序号保留；偏移同时作用于起点与终点，不应用 LRC 的 offset 元数据。零时长、倒置、越界、乱序、重复序号、重复条目、重叠和原文替换字符会记录问题，不自动修正。空字幕保存为 `srt_empty_entry` 标记，不转换成发声结束提示。位置参数保留在问题记录中，不保证按 SRT 布局渲染。

有效区间的显示结束时间仅作为待复核候选，不能自动视为实际发声结束；开启 LRC 空时间戳策略也不会自动采用它。无效字幕区间不会成为有效融合事件。重叠字幕原样保留，如何解释并发语义仍需模型证据和人工复核。

无法解析的时间语法会报错；混入无时间块时记录问题，没有任何带时间条目时导入失败。程序不会为缺失或矛盾的证据编造有效动作。格式兼容测试不代表语义准确性、实际同步或硬件效果已经通过验收。

## WebVTT

VTT 按 [W3C WebVTT](https://www.w3.org/TR/webvtt1/) 的常见字幕结构读取：支持 `WEBVTT` 文件头、BOM、可选字符串标识符、`MM:SS.mmm` / `HH:MM:SS.mmm` 时间和多行正文。毫秒须为三位并使用点分隔，分钟和秒须小于 60。显示区间使用与 SRT 相同的异常诊断和待复核规则。

标识符与布局参数分别保存在 `source_identifier` 和 `source_settings`；NOTE / STYLE / REGION 块保存在问题记录，文件头扩展内容保存在元数据。正文中的 voice、样式、实体和行内时间标签原样保留，包括送给模型的文本；不自动猜测人物身份，不把行内时间标签当作动作锚点，也不执行 CSS 或模拟浏览器排版。原文件保存为 `inputs/subtitles.vtt`。

分段流 VTT 的 `X-TIMESTAMP-MAP` 涉及另一套时钟，当前会明确报错，需先转换为本地完整视频时间轴；不能直接丢弃映射再假定同步。普通独立 VTT 使用从视频播放零点计算的时间；额外校正仍由 `offset_ms` 明确指定。

视频输入及音轨选择见 [视频导入说明](video-inputs.md)。
