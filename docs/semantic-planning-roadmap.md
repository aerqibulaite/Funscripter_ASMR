# 字幕语义规划与连续时间线改造方案

日期：2026-11-10。状态：部分基础已实施，其余为后续设计。依据：当前源码及 `workspace/od010-audit/assessment.md` 的三轨实际素材检查。

实施更新：输入质量视图、新事件契约/旧版读取、无新信息与歧义区分及摘要章节的状态保留已实现；全量 168 项测试通过。当前完成范围及限制见[跨字幕规划说明](semantic-planning-v2.md)。以下仍为整体路线图，不表示全部阶段已交付。

## 目标与边界

先实现可追溯、可复核的跨字幕事件时间线，再逐步验证连续曲线与多轴文件输出。模型负责语言解释，确定性程序负责时间解析、状态更新和数值生成。明确指示、上下文推断及配置默认值必须分别记录来源。

不以一条字幕对应一次变化，不将模型自报置信度、JSON 合格或证据子串命中当作语义正确性的证明。本文不定义特定内容的动作策略、设备运动参数或词语到机械轴的映射。

## 现有能力继续复用

- 项目与修订标识、输入/产物哈希、独立输出目录和原始素材保留。
- 串行两遍规划、上下文预算检查、合格请求缓存、取消与恢复。
- 音频分析副本、特征复用、候选边界及人工确认的优先关系。
- 基础范围/速度检查、数值联动预算、外部修订归档及锁区保护。

这些基础不需要推倒重写。新增模块应接入同一来源与修订检查。

## 第一阶段：规划输入质量检查

主要修改：`subtitles.py`、`planner.py`、`project.py`；可新增 `planning_inputs.py`。

1. 原始 Timeline 保留全部数据；另生成规划输入视图，记录每个 cue 的 eligible/context_only/excluded 状态与原因。
2. 零时长、反向或越界区间默认不作为普通有效目标进入规划；保留显式复核入口，不删除或擅自修正原文。
3. 源文本替换字符、重叠、异常文本长度/显示时长只作为质量提示；不据此自动猜测正确译文或发声时间。
4. 给模型提供区间、时间来源、结束时间是否推断、相关异常和已知说话人标签。缺少标签继续保留未知。
5. 排除无效 cue 后，仍需为原输入建立完整处理清单，避免它们以“遗漏字幕”的形式静默消失。

验收：05 轨零时长 cue 保留在原 Timeline 与复核表，但不作为普通有效目标发送；重叠和 U+FFFD 均能追溯。继续兼容只有候选终点的 LRC。

## 第二阶段：事件契约升级

主要修改：`models.py`、`planner.py`、`fuse_project.py`、`fusion.py`、`tools/export_schemas.py`。

使用独立的新规划版本，保留现有 1.3 读取路径；不要直接改变旧文件中已有字段的含义。

将一对一的 event/cue 关系改为两个集合：

- `cue_assessments`：每个输入 cue 恰好一条，状态为 processed/no_new_information/ambiguous/excluded/failed，并给出原因及关联事件 ID。
- `events`：可为零到多条，每条携带一个或多个 `source_cue_ids`，以及逐条绑定源 cue 的原文证据。

事件应包含：

- 独立稳定 event_id、来源 cue IDs 与 evidence 引用。
- 指示的语言功能，例如直接要求、问句、描述、条件、引用或不确定。
- 适用对象与说话人；未知允许明确为空，不强行推断身份。
- 相对/绝对变化的区别、先后关系，以及是否被后续事件撤销或替代。
- 时间锚点类型、候选时间范围、时间来源与复核状态。
- 明示、推断或人工确认的来源类型。数值参数默认值属于配置来源，不包装成原文结论。

校验仍要求全部 cue 都有处理结果，但取消每个 cue 必须恰好一个事件的限制。多 cue 事件必须拥有合法证据、无越界引用；事件依赖不得成环，重复事件不得重复应用。

迁移不能只修改 `SemanticEvent`：`fuse_project.load_semantics` 也假定 cue 唯一且 event/failure 覆盖全部字幕，必须同时升级。融合端 `CORE_FIELDS`、event_identity、来源哈希、Schema 导出、诊断和修订读取均需配套调整。

验收：多句无新信息只产生覆盖记录；同 cue 的两个合法事件可被读取；一事件引用多 cue 可追溯；非法/缺失处理记录仍被拒绝；旧 1.3 产物维持原解释或通过显式迁移进入新目录。

## 第三阶段：连续状态与冲突管理

主要修改：`fusion.py`；可将纯状态更新提取到 `planning_state.py`。

- 区分无新信息、含义不确定、处理失败和明确结束。不要让一个 unknown 同时代表所有情况。
- 无新信息在适用范围内延续状态；未处理/失败区间不能伪装成已确认延续。
- 暂停状态与可恢复状态分开保存；反复接收同一事件不得叠加变化。
- 场景区间与摘要章节分开。摘要换章不应自动被解释为实际状态改变；重置需要明确的边界语义或配置规则。
- 长空档的延续范围和失效规则显式配置并可复核，避免无限继承或逐句重置。
- 不以字幕行顺序替代同时发生事件的优先级。未知说话人或冲突事件需要独立处置结果。
- 显式设置初始值和补全策略；每个补全字段保留配置出处。

验收：加入中性闲聊不应无故改变既有计划；分块方式变化不重复应用同一事件；失败块不携带过期状态；同时冲突不静默采用最后一行。

## 第四阶段：可追溯的词语与序列候选

可新增 `text_cues.py` 和版本化词表配置；保持其结果为文本候选。

- 保留原文，记录规范形式、别名、语言/来源及词表版本；别名需有依据，不盲目合并相似拼写。
- 词语命中产生位置和上下文候选，不能绕过否定、引用、条件与问句分析。
- 数字和序列识别应支持跨 cue、重复、缺项、重新开始以及普通数量表达的排除。
- 将候选与模型结果对照，发现遗漏和解释冲突；不以关键词规则直接执行设备动作。
- 词表、规范化实现与提示示例的内容哈希都应进入规划签名与请求缓存键。

验收使用中性序列与文本样本：数量描述不误判为序列，重复数字保留证据，不凭缺项自动补出发声时间。

## 第五阶段：事件定位与音频证据

主要修改：`boundaries.py`、`planner.py`，新增独立时间解析模块 `event_timing.py`。

- 字幕时间用于初始候选区间；已确认边界、声学候选和人工确认必须区分等级。
- 模型可以输出“在某段原文之后”及事件顺序，程序只在存在对齐证据时解析成精确时间。
- 缺少句内时间时保留范围与未定位状态。不要把长字幕等分所得时间写成已验证时间。
- 向模型提供有界且带来源的音频摘要；默认能量和周期候选仍不能证明声音事件类别。
- 句尾检测和句内事件定位分开设计；当前 VAD 端点不等于词级对齐。
- 多 cue 引用仍映射到同一分析音频零点，统一处理偏移。
- 对重叠字幕区间先建立合法场景时间线或待解决边界，避免 ID 覆盖通过后才在融合阶段全局失败。

验收：实际 04 轨 20 ms 重叠案例能得到明确的边界处置结果；没有依据时不伪造精确锚点；05/06 的长字幕与长空档可被标为时间证据不足。

## 第六阶段：生成器与多轴接口

主要修改：`motion.py`、`multiaxis.py`、`fuse_project.py`、相关 Profile 与诊断读取。

- 先固定单轴事件时间线的正确性，再接通已有多轴契约。
- 让生成器消费已解析、经过检查的时间区间及显式 Profile；不要直接消费原始模型文本。
- 保存位置、状态和必要的相位信息，使无变化的区间拆分不改变输出；参数变化的衔接策略独立配置。
- 每轴沿用已配置限值，继续检查最终曲线与联动规则；轴方向和实际机械联动需以目标设备校准为依据。
- 语义清单、数值清单、播放器验证及硬件验证分别记录，只有实际应用语义计划时才将 semantic_plan_applied 设为 true。
- 人工锁区/修订保护、局部重生成和诊断必须识别同一个新计划版本。

验收：相同已解析事件、Profile 和实现版本产生相同点集；仅改变证据分块不重启动作相位；非法范围/速度或联动阻断仍生效；设备未验证时清单不宣称通过。

## 第七阶段：真实模型与可编辑复核

- 先以中性合成/人工标注数据验证软件契约和时间线。真实素材评估另建私有参考集，分别标注语义、时间及歧义。
- 固定模型标识、量化备注、提示词、配置和词表版本；设置独立评估集，避免调试样本与验收样本重合。
- 分别衡量事件误报/漏报、条件/否定/问句误判、时间定位误差、连续性问题及人工修订量。没有参考标注时不报准确率。
- 将预览重点放在“来源台词 → 解释 → 候选事件 → 状态变化 → 输出区间”，并提供逐项保留、修改、驳回和边界调整。
- 复核结果保存成独立修订，不直接修改模型原始返回，也不自动成为未经审查的新词表规则。

## 推荐实施批次

| 批次 | 内容 | 完成标准 |
| --- | --- | --- |
| A | 输入视图、异常隔离、上下文质量字段 | 真实素材异常不再作为无标记普通目标进入规划 |
| B | 新事件契约、双版本读取、来源与缓存升级 | 零/多事件和跨 cue 事件能端到端通过规划/融合读取 |
| C | 连续状态、场景边界、冲突处置 | 无新信息不会无故重置，失败与冲突不会被掩盖 |
| D | 文本候选与时间解析 | 保留序列和词语依据，未定位事件不伪装成精确时间 |
| E | 连续生成及多轴接入 | 通过数值契约，完整保留来源与人工修订保护 |
| F | 真实模型与外部播放验收 | 有独立参考和实际运行记录，可量化人工修订成本 |

首批建议实施 A，随后 B+C。A 能先消除已实测的输入缺陷，B+C 才是取消“一句一个事件”限制并建立连续时间线的核心。词表扩充不能替代这三项。
